# Sparse Stage 1 face observation graph

`--refine_observation_graph` records sparse graphs for multi-round RL training and the RL branch of multi-branch evaluation. It does not change actions, gradients, reward, or checkpoint policy dimensions: the existing shared `CandidatePolicy` MLP still makes the decisions. It is not a GNN. Multi-branch graph recording requires a current candidate-policy checkpoint. `--refine_graph_self_loops` adds self-loops; otherwise they are absent.

Each round writes an NPZ before refinement and another after the split and optimization. The latter is constructed anew using the updated mesh and newly rendered selection views; it contains `parent_face_id` indexed by the **new global face ID**, pointing to the previous global face ID. No graph-node index is a lineage ID. Round JSON records absolute paths to these files, including when a segment is resumed in another output directory; moving the files requires updating those references.

`build_face_graph` returns the graph dictionary, ordered candidate face IDs, unchanged MLP candidate features and candidate metadata. `save_face_graph` stores these arrays without pickle:

- `node_to_face` and `face_to_node`: current snapshot's node/global-face maps; `-1` means no node because the face is geometrically invalid.
- `edge_index`: shape `[2, E]`, directed node indices, both directions for each valid shared edge. `edge_vertices` gives the two global vertex IDs; self-loops use `[-1,-1]`.
- `node_features`: nine existing normalized MLP features plus `rgb_missing`. `raw_node_features` gives unnormalized area, RGB mean, gradient EMA, normal-angle mean, view count, pixel count and budget fraction; missing raw values are NaN. `rgb_valid`, `gradient_valid`, `curvature_valid` are separate masks. Scales and definitions are in `metadata_json`.
- `edge_features`: shared-edge length in scene units and unsigned angle in radians, both unnormalized. `edge_feature_valid` marks usable values; self-loop edge features are zero and invalid.
- `candidate_mask` follows the current observed/area filter. `decision_mask` additionally requires positive remaining budget; it does not promise that the requested edge fits the remaining budget or avoids a conflict. `graph_budget_state` creates a feature/mask view for a changed remaining budget. Existing decision records contain the exact sequential feature and sampled action for training and evaluation. The saved before/after graphs are snapshots, not a separate graph for every sampled action.
- `metadata_json` records node/edge counts, boundary edges, nonmanifold edges, invalid faces, loop setting, budget and normalization details. Counts and adjacency are computed over geometrically valid faces. Mesh edges with one such face are boundaries; edges with more than two are counted but omitted from message-passing adjacency, with no clique expansion. Isolated faces remain nodes.

For example: `g, candidates, mlp_features, info = build_face_graph(vertices, faces, sums, pixels, view_counts, num_views, vertex_ema, vertex_seen, remaining, round_budget)`. Arrays are NumPy and can be converted to torch tensors explicitly when implementing message passing later. No dense face-by-face adjacency is allocated. The recorded post-split graph uses the **remaining budget of the completed round**; the next round's graph is rebuilt with its new round budget.

## Two-layer GNN policy

`--refine_policy gnn` enables a shared `SparseFacePolicy` for multi-round training; `mlp` remains the default. Both layers use directed edges, tanh message and node updates, and mean aggregation with `index_add` (isolated nodes receive a zero aggregate). Messages include `log1p(edge_length / sqrt(candidate_area_scale))` clipped at 5, angle / pi, and the two edge-valid bits. Self-loops, if requested at training, are part of the architecture input and are restored during evaluation. Existing graph features use candidate-derived scales. The two layers receive all graph node features **except budget**; embeddings are computed once per round. The action head receives the selected candidate embedding plus its actual current remaining/per-round budget, before each request/hold decision. Graphs are rebuilt from each current mesh. No dense adjacency or external graph library is used.

For each training round the trajectory embeds the sampling graph arrays and face/node mappings, alongside sampled actions, decision masks and per-decision budget features. At the policy update it recomputes graph embeddings and log probabilities from those same arrays, retaining gradients through both message layers. This preserves the existing per-face return weighting and its shared-edge/conflict approximations. Parent/child returns continue to use global face IDs and `parent_face_id`, never graph-local indices. Graph observation NPZs remain optional; GNN training always records the graph state needed to resume a pending return segment, so checkpoints grow with graph size and horizon.

Checkpoints declare `policy_type` and `policy_architecture`: older candidate MLP checkpoints default to `mlp`; a GNN cannot silently resume as an MLP or vice versa. Train a new GNN from a Stage 1 checkpoint, then resume with the same `--refine_policy gnn` and graph self-loop setting. To compare fixed MLP and GNN policies in one multi-branch run, use `--refine_multibranch_policy MLP_TRAJECTORY --refine_multibranch_compare_policy GNN_TRAJECTORY` (order can be reversed). Both trajectories must use matching original checkpoint/mesh hashes, candidate fraction, minimum area and EMA beta. Both share initial state, sampled training views, optimization steps and budget limits; actual added faces and remaining budget are recorded independently. Per-face NPZs additionally contain `selection_region_local_reward` and `face_cost`, calculated with one common set of evaluation reward weights on the fixed pre-split selection-view regions. This is an evaluation diagnostic, not a policy update or a lineage return; independent-view full-frame metrics remain the primary comparison. The two policy checkpoints may have been trained with different reward weights, which are recorded for each branch.

## Budget-ranked policy evaluation

Multi-branch evaluation defaults to `--refine_multibranch_policy_mode threshold`, preserving the sequential `p >= 0.5` policy. Select `--refine_multibranch_policy_mode rank` to request candidates in descending current predicted probability, even when all probabilities are below 0.5. This mode changes evaluation behavior and is not a threshold-policy result or a policy-gradient sample. It is available for both current candidate MLP and GNN checkpoints, with identical candidate and tie rules (equal scores use ascending global face ID).

The selector calculates all remaining candidates' scores at the current budget. It recomputes and re-sorts whenever a successful split changes the remaining budget; conflicts, already-split edges and rejected attempts do not change the budget and do not cause a rescore. GNN node embeddings are cached within that round because they do not contain budget; each score uses the latest budget in its action head. The pre-split topology and node features remain fixed for the round, consistent with the current simultaneous edge-split implementation. Scoring and sorting every remaining candidate after each successful split can be expensive on large meshes.

Each round records `policy_evaluation_mode`, initial-candidate and attempted-at-current-budget probability distributions, considered/requested/executed counts, conflicts, already-split edges, budget rejections, not-considered candidates, actual added faces, unfilled budget, and independent-view metrics. The face NPZ records `initial_probability`, per-attempt `request_probability`, `decision_order`, `remaining_budget` and decision mask. Initial scores are all evaluated at the initial round budget; attempted scores generally use different remaining budgets. Rank-mode `decision_log_probability` is NaN because deterministic ranking is not a Bernoulli sample. Existing legacy policies continue to use their historical ranking and are labeled `legacy_rank` in their branch records.

## Texture-aware GNN and optional gradient reward

New `--refine_policy gnn` training uses `face_gnn_two_layer_texture_v2` and `sobel_foreground_rgb_v1`. The original `face_gnn_two_layer_v1` GNN and MLP checkpoints remain loadable for evaluation; they cannot be resumed as the new architecture. Begin texture GNN training from Stage 1, and resume only with a matching texture checkpoint. Multi-branch comparison supports old-vs-new GNN as well as MLP-vs-GNN.

Training and evaluation use the same Sobel implementation on selection views only. Both images use the configured `--color_space` as returned by `eval_step` (default sRGB; `linear` if selected), with fixed white background. Kernels are conventional Sobel divided by 8. Replicate padding is applied but the one-pixel image boundary is invalid. A pixel is eligible only when its entire 3x3 stencil has finite RGB and target alpha >= 0.999; selection features additionally require rasterized mesh coverage throughout the stencil. The stencil can span adjacent faces: attribution is to the center pixel's pre-update face. Thus neither random backgrounds nor semitransparent silhouette edges become texture observations. Predictions outside the current mesh use fixed white, never random colors.

For each eligible pixel, texture strength is `sqrt(mean_RGB(gx^2 + gy^2))`; gradient error is PyTorch SmoothL1 averaged over six RGB/x/y components. Sums and counts are combined across views before division. Node input adds `log1p(T / median_positive_candidate_T)`, `log1p(E_grad / median_positive_candidate_E_grad)`, each clipped at 5, plus one missing flag; a zero/empty median uses scale 1. The candidate rule and old nine MLP features are unchanged. Graph metadata records definitions, counts and scales; texture node raw averages, valid flags and pixel counts are preserved in the trajectory's `policy_graph` and optional graph NPZ. The feature version is checked at policy load and resume. Dynamic budget remains exclusively in the action head.

`--refine_multiround_grad_weight` defaults to 0. With a positive value the existing reward gains `weight * (before_error - after_error)` on the same reward views and fixed old-face pixel regions. The region uses the pre-split 3x3 eligible coverage mask and old face ID; after-split foreground/finite validity is also checked, but after-split face ownership is deliberately not required, so pixels moving outside the mesh remain measurable. Counts and before/after error are recorded. RGB, silhouette and gradient validity are checked independently: unavailable components are skipped, and a face retains a reward if at least one reconstruction observation and its face cost are valid. Missing components are recorded as missing, including when their weight is zero. A face with no valid reconstruction observation or invalid cost has an invalid total reward. The total can thus contain different subsets of components across faces; this is not equivalent to measuring a missing improvement as zero. Edge outcomes record requesting and passive faces separately and combined, while the existing one-time split cost and area-weighted lineage rules remain unchanged. This is a policy input/reward only and does not add a mesh optimization loss.

## Independent-view texture metric

Multi-branch comparison reports `gradient_error` and `gradient_valid_pixels` alongside existing RGB and silhouette metrics in `initial_metrics`, each round's `metrics`, and `final_metrics`, both per view and overall. The gradient error uses the same Sobel / 8 and mean SmoothL1 across RGB and x/y directions as the texture feature. Images use the configured evaluation color space and fixed white background. The overall metric is weighted by valid pixels across views; an empty set reports `null` and zero pixels.

Before any branch runs, each evaluation view gets a fixed target-only mask: the complete 3x3 target stencil must have finite RGB and alpha >= 0.999. Replicate padding is used for Sobel, but the outer image boundary is excluded from this mask. Mesh coverage and face IDs never enter this metric. The masks are saved once in `evaluation_gradient_masks.npz` and their path, SHA-256 and metric definition are recorded in `multibranch_comparison.json`. Every subsequent observation must match the same target mask. If a rendering is nonfinite anywhere in a selected 3x3 stencil, evaluation raises an error rather than changing that branch's pixel set. These independent views are reporting only and never feed the policy, candidate selection or policy rewards. `rank` and `threshold` retain their existing labels and behavior.

### Reward component diagnostics and continuation

Each round's `reward_groups` records executed requesters, passive neighbors, rejected and not-considered faces. `independent_components` includes each component's valid count, missing-reason counts, raw improvement distribution, weighted contribution distribution and total reward distribution. `split_face_rewards` provides the same values per executed requester and passive neighbor. All faces also have `reward_component_reason_codes`, with the `reward_reason_codes` mapping in metadata: 0 valid, 1 no pixels, 2 nonfinite before, 3 nonfinite after, 4 invalid cost, 5 invalid pixel count. `reward_status_codes` records 0 valid, 1 no valid reconstruction observation, 2 invalid cost. The previous `same_valid_set` statistics are retained for comparisons on a shared RGB/silhouette-valid subset.

Reward semantics are versioned `partial_observation_components_v2`. An old completed compatible texture-GNN trajectory can start a new segment with changed weights: it retains the current mesh, model, policy and vertex EMA, resets the policy optimizer when reward semantics or weights differ, and records the transition in the checkpoint and metadata. An unfinished old segment cannot cross the reward-version or weight boundary; complete it with the previous code, use a completed checkpoint, or start from Stage 1. Old pre-texture GNN weights remain architecture-incompatible with the texture GNN. Starting from Stage 1 produces the cleanest independent experiment.

## Optional Stage 1 image-gradient optimization loss

`--lambda_image_grad` defaults to 0 and is independent of the RL gradient-reward weight `--refine_multiround_grad_weight`. If positive, `Trainer.train_step` adds the mean Sobel-gradient SmoothL1 over valid foreground centers to the mesh/appearance optimization loss; the per-face RGB error accumulator and RL rewards are unchanged. The same implementation is used by ordinary Stage 1 training and multi-round `_train_branch` optimization.

The Sobel / 8 kernels, configured RGB color space, replicate convolution padding, six-component RGB/x/y average, and 3x3 validity rule match texture observations. Centers at the image border, stencils containing nonfinite inputs, and stencils containing target alpha below 0.999 are excluded. RGBA training images or an explicitly supplied foreground mask are required. Unlike face selection, this loss does not require current mesh coverage: missed foreground can still contribute. Zero valid centers produce a graph-connected zero loss and a recorded count of zero.

To prevent random-background edges without a second render, the training image is algebraically recomposited from its differentiable antialiased alpha and original background onto white; the target is composited on white as well. This preserves the render's existing color-network and permitted vertex-gradient paths, including SSAA downsampling. Logs contain unweighted `loss_image_grad`, `weighted_loss_image_grad`, and `image_grad_valid_pixels`; multi-round JSON `training_losses` contains per-step values and means. Different mesh-loss settings at a completed trajectory boundary are allowed and recorded in run options. A pending trajectory may resume only with the same setting; an old checkpoint without this option is equivalent to zero. The policy architecture and reward version are unchanged, but continued training with a changed mesh loss is a different experiment.

## Hybrid candidates and categorical budget decisions

The existing default `--refine_candidate_mode area` retains the previous area-only rule. Select `--refine_candidate_mode hybrid` for the first experiment's defaults `--refine_area_fraction 0.4 --refine_texture_fraction 0.1`. A valid face has finite area above the existing threshold, at least one selection-view RGB observation and finite RGB error. For N valid faces, choose the top `ceil(N * area_fraction)` by descending area, then enough remaining faces by descending observed mean texture-gradient error to reach `ceil(N * (area_fraction + texture_fraction))`. Both fractions refer to N. Equal scores use ascending global face ID. A face without a finite, positive-count texture observation never participates in texture ranking. If too few texture observations exist, fill the remaining slots by area. Counts, IDs and RGB/texture error coverage for the area, texture and fallback groups are recorded in `candidate_info`. Unselected geometrically valid neighbors stay in the message-passing graph.

`--refine_action_mode categorical` is a new GNN-only policy architecture, `face_gnn_texture_categorical_v3`. At each step, it uses the current budget fraction in the action head and applies a softmax to scores of all unprocessed candidates; training samples one face without replacement, while multi-branch evaluation with `--refine_multibranch_policy_mode rank` greedily takes the highest current score. Every chosen face requests its longest edge. Actual added faces determine the new budget; failed or conflicting requests consume no budget, and processing continues so a boundary edge costing one face can still fit. Static graph embeddings are cached only within the current round, and action scores are refreshed when the budget changes. With `--refine_rank_stop`, an additional learned stop logit competes in the same softmax in training and the same argmax in evaluation; its default is disabled. The saved candidate IDs, exact sampled order, per-action conditional probabilities, budgets, event statuses and graph allow each eligible set to be reconstructed by removing preceding actions. Unprocessed faces after a stop are labeled `stopped`, distinct from budget exhaustion. The existing Bernoulli request/hold mode is still the default.

Policy updates replay the exact per-step without-replacement log-softmax denominator at the recorded budget, not independent Bernoulli log probabilities. Each executed requester is weighted by its face lineage return plus valid passive-neighbor returns; a rejected or already-passive request receives zero direct split credit, while it remains part of other decisions' softmax denominators. Missing returns are excluded from direct weighting. If stop is sampled, the mean valid return of remaining non-passive faces is used as its local credit proxy. Baseline, scaling and clipping are applied as configured. This per-action/local-return allocation is an approximation to the coupled global return: actions can change future eligibility and shared-edge topology, and the stop proxy is not an exact counterfactual. It must not be interpreted as proof of an unbiased global policy gradient. Checkpointed action-head evaluation recomputes activations during backward to reduce peak memory, but scoring all remaining candidates at each budget/decision can be costly on 100k-face meshes.

Categorical and Bernoulli checkpoints have distinct action/architecture versions and cannot resume across modes. Start a categorical policy from Stage 1; a matching categorical checkpoint can resume with the same candidate and stop configuration. Multi-branch evaluation loads each policy's stored candidate rule and reports it per branch, so comparisons between older area-only and new hybrid policies include that candidate-rule difference. GNN categorical evaluations are labeled `categorical_greedy`, not Bernoulli threshold or sigmoid-ranking evaluations.

## Optional per-face gradient diagnostics

Add `--refine_face_gradient_diagnostics` to multi-branch evaluation. It is disabled by default and does not alter policies, candidate selection, rewards, optimization or budgets. It writes `gradient_diagnostics_<branch>_round_<NNNN>.json` plus a matching `.npz`, linked from each branch round in `multibranch_comparison.json`. Diagnostics use **validation selection views**, separately labeled from independent evaluation views; the existing independent-view RGB, silhouette and gradient metrics remain unchanged. Every branch, including high-error and random seeds, gets the same diagnostics.

The five reported groups are all visible valid faces, a diagnostic hybrid reference set, executed requesters, passive neighbors and unchanged faces. A visible valid face has a selection-view RGB observation, finite RGB error, and finite area above the minimum area threshold. To make the hybrid group comparable across methods without changing their actual decisions, the reference uses the first supplied hybrid checkpoint's area/texture fractions and minimum area, or the command-line defaults if neither policy is hybrid. The actual candidate rule remains recorded separately, and the NPZ includes `actual_policy_candidate` and `hybrid_candidate` masks. A branch's face IDs refer only to that branch and round.

Pre-split per-face gradient error uses the same Sobel / 8 and 3x3 opaque target/mesh coverage mask as the texture feature, summed over selection views before dividing by valid pixels. Each group's `pre_valid_faces`, `pre_valid_pixels`, mean and median of per-face means, and `pre_pixel_weighted_error` describe that sample. The coverage numerator is the sum of those valid per-pixel SmoothL1 gradient errors over the group. The denominator is the same sum over **all visible valid faces** in that branch before this update; zero denominator produces `null`, not a percentage.

Before/after improvement uses each old face's **same pre-split pixel locations** and the original valid stencil. The after error is included even if that location loses mesh coverage or is covered by a child of another old face, provided the after RGB stencil is finite. Output `parent_face_id` maps each new global face to this round's old global face; no graph indices are used. A location whose after face ID or parent ID is malformed, or whose old face has no valid child mapping, is excluded from paired error and counted as invalid correspondence. Lost coverage, coverage by a different old parent, invalid after RGB/stencils, missing children and faces without valid gradient pixels are reported separately. Their counts can overlap. Group changes include unweighted face mean/median improvement, pixel-weighted improvement and fraction of valid faces with positive improvement; undefined values are `null` in JSON and NaN in the numeric NPZ. Zero-valued count fields mean none, not an imputed error.
