# Sparse Stage 1 face observation graph

`--refine_observation_graph` records sparse graphs for multi-round RL training and the RL branch of multi-branch evaluation. It does not change actions, gradients, reward, or checkpoint policy dimensions: the existing shared `CandidatePolicy` MLP still makes the decisions. It is not a GNN. Multi-branch graph recording requires a current candidate-policy checkpoint. `--refine_graph_self_loops` adds self-loops; otherwise they are absent.

Each round writes an NPZ before refinement and another after the split and optimization. The latter is constructed anew using the updated mesh and newly rendered selection views; it contains `parent_face_id` indexed by the **new global face ID**, pointing to the previous global face ID. No graph-node index is a lineage ID. Round JSON records absolute paths to these files, including when a segment is resumed in another output directory; moving the files requires updating those references.

`build_face_graph` returns the graph dictionary, ordered candidate face IDs, unchanged MLP candidate features and candidate metadata. `save_face_graph` stores these arrays without pickle:

- `node_to_face` and `face_to_node`: current snapshot's node/global-face maps; `-1` means no node because the face is geometrically invalid.
- `edge_index`: shape `[2, E]`, directed node indices, both directions for each valid shared edge. `edge_vertices` gives the two global vertex IDs; self-loops use `[-1,-1]`.
- `node_features`: nine existing normalized MLP features plus `rgb_missing`. `raw_node_features` gives unnormalized area, RGB mean, gradient EMA, normal-angle mean, view count, pixel count and budget fraction; missing raw values are NaN. `rgb_valid`, `gradient_valid`, `curvature_valid` are separate masks. Scales and definitions are in `metadata_json`.
- `edge_features`: shared-edge length in scene units and unsigned angle in radians, both unnormalized. `edge_feature_valid` marks usable values; self-loop edge features are zero and invalid.
- `candidate_mask` follows the current observed/area filter. `decision_mask` additionally requires positive remaining budget; it does not promise that the requested edge fits the remaining budget or avoids a conflict. `graph_budget_state` creates a feature/mask view for a changed remaining budget. Existing decision records contain the exact sequential feature and sampled action for training and evaluation. The saved before/after graphs are snapshots, not a separate graph for every sampled action.
- `metadata_json` records node/edge counts, boundary edges, nonmanifold edges, invalid faces, loop setting, budget and normalization details. Counts and adjacency are computed over geometrically valid faces. Mesh edges with one such face are boundaries; edges with more than two are counted but omitted from message-passing adjacency, with no clique expansion. Isolated faces remain nodes.

For example: `g, candidates, mlp_features, info = build_face_graph(vertices, faces, sums, pixels, view_counts, num_views, vertex_ema, vertex_seen, remaining, round_budget)`. Arrays are NumPy and can be converted to torch tensors explicitly when implementing message passing later. No dense face-by-face adjacency is allocated. The recorded post-split graph uses the **remaining budget of the completed round**; the next round's graph is rebuilt with its new round budget.
